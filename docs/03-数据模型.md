# 03 · 数据模型

结构来自历史协议研究与公开实现交叉核对。以下 ID、金额、日期及名称全部是人为构造的示例，不包含真实账单或账号统计。当前实现差异见 [协议补充](./06-网页版协议补充与验证.md)。

## 1. 账单对象（Bill）

`/syncv2/pull` 的 `changes` 返回账单。可选字段可能缺失。

| 字段 | 含义 |
|---|---|
| `id`、`userid`、`bookid`、`cateid` | 账单、用户、账本及分类 ID；网页统一使用字符串 |
| `time`、`createtime`、`updatetime` | 发生、创建及更新时间，Unix 秒 |
| `money` | REST API 基准币种金额；使用十进制字符串精确运算 |
| `type` | 账单类型 |
| `status`、`platform` | 状态及客户端平台；查询常见 1/0，写入契约另见协议补充 |
| `remark` | 可选备注 |
| `assetid` | 关联资产；`-1` 表示未指定 |
| `extra` | 外币、退款、报销、标签等扩展信息 |

```json
{"id":"8100000000000000001","userid":"example-user","bookid":"-1","cateid":"101","type":0,"time":1767225600,"money":"12.50","remark":"示例午餐","status":1,"assetid":"-1"}
```

真实上游可能使用 JSON 数字传输 ID。必须从响应原始文本无损解析，包含嵌套字段、删除数组和未知字段。普通 `JSON.parse` 的 reviver 无法恢复已舍入的大整数，也不能依赖只匹配顶层 ID 的正则。

## 2. 账单类型

| type | 含义 | 当前统计处理 |
|---|---|---|
| 0 | 支出 | 普通支出 |
| 1 | 收入 | 普通收入 |
| 2 | 转账 | 单列 |
| 3 | 信用卡还款 | 单列 |
| 5 | 报销相关 | 单列；不同版本语义仍需核对 |
| 20 | 退款 | 按退款发生期间抵扣原账单分类支出 |
| 其他 | 未确认 | 单列，不计入普通收支 |

退款是独立账单，`extra.refundsid` 指向原账单。示例：支出 100 元、次月退款 20 元，两个月分别统计支出 100 元和退款抵扣 20 元。

## 3. 账本与成员

`bookid=-1` 表示默认账本。账本信息以 `/client/init` 的 `books` 为准；常见字段为 `bookid/name/type/members/config`。`config` 等字段可能不存在，不据此推断账本无效。

成员信息来自 `books[].members`。示例 ID `81000000000000001` 仅为精度测试，不指向真实账本。

## 4. extra 扩展字段与金额口径

```json
{"curr":{"ss":"JPY","sv":"10000","ts":"CNY","tv":"500.25","bs":"CNY","bv":"500.25"}}
```

这是虚构的换算示例，不代表当前汇率。同一记录在 REST API 中 `money` 是基准金额 `500.25`，客户端 SQLite 可能存原币金额 `10000`。网页版使用 REST API，不重复换汇。

| 字段 | 用途 |
|---|---|
| `refundsid` | 原账单 ID |
| `rfds` | 原账单的退款关联 |
| `bxs` | 报销关联 |
| `tags` | 标签 ID 集合，可能为 null |
| `curr` | 原币和历史换算信息 |
| `transfee` | 手续费 |
| `baoxiaoed/baoxiaotime/baoxiaov` | 旧版报销信息，兼容性待验证 |

## 5. 分类对象（Category）

```json
{"id":"102","name":"示例早餐","type":0,"bookid":"-1","parentid":"101","level":2,"sort":0}
```

`parentid=-1` 表示一级分类，其余为父分类 ID。同步接口提供包含二级分类的集合，单独分类接口的完整性需核对。统计归并时跟随父分类，不按名称猜测关联。

## 6. 币种对象（Currency）

常见字段：`symbol/name/sign/baseprice/pricetime/iscommon`。`baseprice` 为汇率字符串，`pricetime` 为更新时间。应用显示上游更新时间，不使用当前汇率改写历史金额。

## 7. 预算对象（Budget）

```json
{"budgetid":"81000000000000002","bookid":"-1","type":1,"typeinfo":"2026,1","flag":1,"cateid":null,"money":"1000","used":"125.50"}
```

`type=1/2` 分别表示月度/年度，`typeinfo` 为 `年,月` 或 `年`。`flag=1` 为总预算，`flag=2` 为分类预算。分类预算可带 `category/count`。`daystats` 中 `datetime/totalspend/spend` 表示日期、累计支出和当日支出。

## 8. 本地 SQLite 数据库（备用数据源）

macOS 客户端的标准路径为 `~/Library/Containers/com.mutangtech.qianji.fltios/Data/Documents/qianjiapp.db`。这是软件标准路径，不是本项目部署地址。

研究中涉及 `user_bill/category/user_book2/user_budget/user_asset/bill_tags8` 等表。网页版不读取客户端数据库；本地数据与 API 在字段缺失、币种口径和同步时效方面存在差异。数据库可能包含完整身份和财务数据，不放入源码、镜像或 CI 工件。
