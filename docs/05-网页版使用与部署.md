# 钱迹网页版使用与部署

## 功能与边界

界面包括总览、账单明细、收支统计、预算、账本与资料、设置。默认中文、北京时间，桌面优先并支持手机。

- 按账本、发生日期、类型、分类（含子分类）、成员、标签、金额和备注筛选账单；分页和 CSV/JSON 导出遵循相同筛选条件。
- 金额由 decimal.js 精确计算；大整数 ID 在内部及浏览器接口中始终为字符串。CSV ID 前加单引号避免表格软件截断，JSON 保留纯 ID 字符串。
- 退款在其发生期间抵扣支出，以原账单的分类归属汇总；原账单缺失时使用退款自身分类并提示。转账、还款、报销与未知类型单独列示，不混入普通收支。
- API `money` 按已换算的基准金额处理，详情另列 `extra.curr` 原币信息，不按当前汇率重新计算历史记录。
- 月度/年度预算按账本分别查询；总览选择全部账本时，预算卡片明确显示默认账本预算。
- 账本/成员/分类来自同步快照；资产、借贷、标签、币种与预算为在线查询。接口形状不符合已知结构时显示错误，不将异常当成空数据。
- 不实现缺失 API 的账本、分类、资产、标签和预算增删改，不支持离线写入、储蓄计划或分期。
- 报销语义在旧版本和新版本间存在差异，当前统计单列 type=5，不宣称与所有钱迹报表口径完全一致。`extra.flag` 等尚未覆盖的高级统计排除规则不纳入当前口径。

## 本机运行

Node.js 22.13+（推荐最新 Node 22 LTS），npm。

```bash
npm ci
npm run dev
```

前端地址 [http://localhost:5173](http://localhost:5173)，API 在 3001 端口。开发服务器把 `/api` 转发到后端。首次真实登录自动全量同步，之后点击「同步账单」进行增量同步。

生产模式：

```bash
npm run build
npm start
```

打开 [http://localhost:3001](http://localhost:3001)。生产服务同时提供静态前端与 API。

`npm start`、`npm run dev` 和 `npm run backup` 会读取存在的 `.env`；首次可复制 `.env.example` 并修改。已有系统环境变量优先。

## Docker 自部署

```bash
docker compose pull
docker compose up -d --no-build
docker compose ps
```

Compose 创建 `qianji-data` 命名卷，运行时使用非 root 用户，容器有健康检查和自动重启策略。默认仅绑定宿主机 `127.0.0.1:3001`，不直接开放公网。

公网使用自己的 HTTPS 反向代理转发至 `http://127.0.0.1:3001`，并配置：

```dotenv
APP_ORIGIN=https://money.example.com
COOKIE_SECURE=true
ENABLE_DEMO=false
```

更新环境后执行 `docker compose up -d`。`APP_ORIGIN` 必须与浏览器的协议、域名、端口完全一致，不含尾随 `/`。不匹配会拒绝登录、同步和其他 POST 请求。Compose 端口绑定可按局域网部署需求调整，并相应更新 Origin。

### Traefik 部署示例

复制 `deploy/home.env.example` 为 `.env`，设置自己的域名和已创建的 Traefik 外部网络。`compose.home.yaml` 是独立配置，不与本机配置合并；它不发布宿主机端口，通过 Traefik 的 websecure 入口访问。

```bash
cp deploy/home.env.example .env
# 编辑 .env，将 qianji.example.com 替换成自己的域名。
docker compose pull
docker compose up -d --no-build
```

示例使用 `./data:/app/data` 保存数据库及密钥。目录应归 UID/GID 1000 所有；Traefik 的证书签发和网络由部署者配置。本仓库不记录任何实际主机。

源码构建可用 `docker build -t qianji-web:local .`，并在 `.env` 设置 `QIANJI_IMAGE=qianji-web:local`。切换版本前备份数据，固定旧镜像 digest 可回滚。

## 配置

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `PORT` | `3001` | Node 服务端口 |
| `HOST` | `0.0.0.0` | Node 监听地址 |
| `DATA_DIR` | `data`，容器中 `/app/data` | SQLite 和密钥目录 |
| `APP_ORIGIN` | `http://localhost:3001` | 唯一允许的生产写入来源 |
| `COOKIE_SECURE` | `false` | HTTPS 部署必须设置为 `true` |
| `ENABLE_DEMO` | `true` | 是否允许独立演示会话 |
| `SESSION_KEY` | 自动生成 `data/.key` | 可选，64 位十六进制 AES 密钥；自管时自行向容器传入 |

上游 token 使用 AES-256-GCM 加密，浏览器仅持有随机会话 Cookie（HttpOnly、SameSite=Strict，HTTPS 下 Secure）。密码及密码 MD5 不持久化，不自动重登。会话保留 7 天；上游 token 失效时重新登录。相同邮箱复用持久化的设备 ID。

单账号个人部署，不提供公开注册或多人权限管理。不同登录账号的数据按 UID 隔离；不应把此部署当作对外托管平台。

## 备份与恢复

应用数据库存放在 `DATA_DIR/qianji.db`，默认密钥在 `DATA_DIR/.key`。数据库含个人账单，应按私有数据保护。

在线一致性备份（使用 SQLite `VACUUM INTO`，不直接复制运行中的 WAL 文件）：

```bash
npm run backup -- ./backups/2026-09-12
```

Docker 内备份到数据卷中的新目录：

```bash
docker compose exec qianji node dist-server/server/backup.js /app/data/backups/2026-09-12
docker compose cp qianji:/app/data/backups/2026-09-12 ./backups/2026-09-12
```

备份目标必须是不存在的新目录。备份包含一致性数据库和自动生成的密钥；若使用 `SESSION_KEY`，需自行保管相同配置值。

恢复步骤：停止应用，保留当前数据目录副本，把备份中的 `qianji.db` 和 `.key` 放入一个全新的数据目录（不要混入旧的 `-wal`、`-shm` 文件），确认运行用户可读写，再启动。不要使用 `docker compose down -v` 清空正式卷。

## 写入测试账本验收

目前真实上游写入没有经过本项目实测，所有功能初始为「待测试账本验证」。代码中的模拟测试不会开放真实账号权限。

1. 在钱迹 App 创建专用空白测试账本，网页版同步后进入「设置」选择并保存。
2. 点击「记一笔」，选择测试账本，新增一笔小额基准币种支出。界面明确提示真实测试写入。上游接受 ID 且回拉字段一致后，新增功能标记为已验证。
3. 在 App 检查分类、金额、备注与时间；网页打开该账单详情，测试编辑后再次核对。
4. 新建另一笔普通支出并测试部分退款。需回拉到唯一退款记录、原账单引用和正确金额，才算通过。
5. 测试报销时新建「待报销支出」，再通过详情进行报销与取消报销。若上游要求账号迁移，应在官方 App 处理；网页版不会自动调用账号级升级。
6. 对没有关联退款或报销的独立测试账单测试删除，回拉确认不存在后通过。
7. 最后在官方 App 检查整个测试账本，并根据需要清理测试记录。删除不是对所有写入的自动回滚。

当前可写范围：支出、收入、待报销支出；基准币种、无资产/图片/手续费。外币、转账、信用卡还款等可查询统计，不能使用通用写入表单修改。已有退款或报销关系的账单不允许通用编辑/删除。

每个写入请求具有独立 UUID，服务端保存状态；重复请求不会重复调用上游。编辑携带原记录版本，提交前同步并检查变更。发送超时或回拉不匹配时，状态为「待核查」，其他新写入暂时阻止：

- 在设置里点击「核查结果」只回拉数据，不重新发送请求。
- 若已在官方 App 明确核实操作没有发生，可点击「已在钱迹核实未发生」解除阻止。此操作仅记录人工处理结果，不会重新提交，也不会解锁未通过验证的功能。
- 不要通过刷新页面或新建相同账单来替代核查。

## HTTP 接口

所有接口在 `/api` 下，除登录、演示、会话状态及健康检查外均需 Cookie。POST 需 `Content-Type: application/json` 与匹配的 Origin。上游地址固定，不允许传入任意代理路径。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/health`、`/auth/session` | 健康与登录状态 |
| POST | `/auth/login` | `{email,password}` 登录 |
| POST | `/auth/demo`、`/auth/logout` | 演示 / 退出 |
| GET | `/bootstrap` | 账号、账本、分类、同步状态和功能状态 |
| POST | `/sync` | `{full?:boolean}`，完整分页成功后原子保存 |
| GET | `/bills`、`/statistics` | 共用筛选参数 |
| GET | `/bills/:id` | 账单、编辑版本和关联记录 |
| GET | `/bills/export` | `format=csv\|json`，共用筛选 |
| GET | `/budgets` | `bookid, kind=month\|year, period=YYYY-MM\|YYYY` |
| GET | `/resources/:kind` | `books/members/categories/assets/loans/tags/currencies` |
| GET | `/settings` | 验证与操作记录 |
| POST | `/settings/test-book` | `{bookid}` |
| POST | `/writes` | `requestId, action, testing, bookid` 及对应表单字段 |
| POST | `/writes/:id/reconcile` | 只核查，不重发 |
| POST | `/writes/:id/resolve` | `{confirmedNotApplied:true}` 人工核实未发生 |

筛选参数：`bookid/from/to/type/category/member/tag/min/max/query`。日期 `YYYY-MM-DD`，`page` 从 1 起，`pageSize` 默认 25、最大 100；统计 `group=day|month|year`。ID 和金额均使用字符串。

```bash

npx playwright install chromium
```
