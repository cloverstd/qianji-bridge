# GitHub Actions 与 GHCR 镜像

仓库：<https://github.com/cloverstd/qianji-bridge>。镜像：`ghcr.io/cloverstd/qianji-bridge`，公开后可匿名拉取。

## 标签与触发

- `main` 推送：验证、构建并发布 `latest` 和 `sha-<完整提交SHA>`。
- `v1.2.3` 等稳定版本标签：发布 `1.2.3`、SHA 标签并更新 `latest`。
- `v1.2.3-rc.1` 等预发布标签：只发布预发布版本及 SHA 标签。
- PR：密钥扫描、测试与双架构构建，不登录 GHCR、不发布。
- 手动触发：main 或合法版本标签才发布，其他分支只验证与构建。

验证使用 Node.js 22、锁文件依赖、类型检查、后端测试、生产构建及 Playwright Chromium。发布使用 GitHub 内置 GITHUB_TOKEN，不需要个人 PAT 或钱迹账号。镜像包含 linux/amd64 和 linux/arm64，附带源码标识、提交、SBOM 和构建来源证明。

## 启动

```bash
docker pull ghcr.io/cloverstd/qianji-bridge:latest
docker compose up -d --no-build
```

首次启动生成空数据库和加密密钥；真实账号只能在自己的实例登录。仓库和镜像均不含真实账单或凭证。Traefik 示例另见部署文档。

生产部署建议在 `.env` 中指定 `QIANJI_IMAGE=ghcr.io/cloverstd/qianji-bridge@sha256:实际digest`，避免 latest 更新时隐式改变版本。digest 从 Actions summary 或 GHCR 包页面取得。

## 发布检查

首次发布需在 GHCR 包设置中确认包为 Public；仓库公开不代表包一定公开。使用临时空 DOCKER_CONFIG 匿名拉取验证，而不是沿用登录后的本机缓存。

```bash
docker buildx imagetools inspect ghcr.io/cloverstd/qianji-bridge:latest
```

预期包含两个运行平台，并附带 attestation manifest。首次发布需验证容器的网页与 MCP 健康检查；MCP 只监听容器回环地址。

CI 不包含部署任务，不读取私有主机配置。生产升级与数据备份由部署者独立执行。

## 脱敏规则

公开历史从新的源码快照开始。Git 忽略运行数据、会话、环境文件、密钥、备份和抓包；Docker 使用构建文件白名单。文档、演示和测试均为虚构样例，金额和 ID 精度边界保留用于回归测试。

提交前审查 `git diff --cached`，对暂存内容执行 gitleaks 扫描并隐藏命中值。测试夹具中的假 token 只在确有误报时按具体行解释，不整体跳过 tests 或源码目录。不要把本地扫描报告、截图、备份、tunnel ID 或已绑定的私人应用配置提交。
