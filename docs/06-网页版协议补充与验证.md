## 已实现的核验策略

- 上游原始 JSON 用 lossless-json 读取，所有数值 token 先保留文本；业务 ID 与金额传给浏览器时为字符串。类型、时间等必要字段再按明确语义转换。
- 每个账单同时保存原始无损 JSON（内部 `_wire`），编辑时复用原始未知字段及数值类型，只覆盖允许修改的字段，并剔除已知展示字段；`_wire` 不通过公开账单接口或导出暴露。
- `syncall` 的数字 ID 和金额以真正 JSON 数字 token 编码，不把长整数强转为 Number。
- 新增/编辑须回拉到相同 ID、账本、金额、时间、类型、分类和备注；金额采用十进制数值比较。
- 删除须通过全量回拉确认该记录不存在。有关联退款/报销时不允许通用删除。
- 退款核查新出现的唯一退款、源 ID、发生时间、备注、金额及源账单 `extra.rfds` 关系。旧版关系不足以明确核对时保留待核查状态。
- 报销核查源账单 `extra.bxs` 和相关账单金额；取消报销核查源关系和状态清空。
- 任何不明确回执或超时不重发。缺少真实回拉证据时不解锁功能。

## 当前验证结论

**已完成本地模拟验证**：签名与请求编码；ID、金额、嵌套数字；跨账本分页、删除、事务回滚；月年统计、退款、外币基准金额；登录与 Cookie、会话加密/恢复；预算参数、未知资源结构；普通账单新增/编辑/删除、退款/报销/取消报销的提交—回拉核验及重复请求去重；桌面和手机浏览器交互。

**未完成真实上游验收**：本次没有使用真实账号。包括新补充的写入协议、非空资产/借贷/标签对象、旧版报销兼容性在内，均不能视作已实测通过。用户需按使用文档在专用测试账本中逐项验证。

公开版保留历史协议结论，所有响应示例改为虚构数据，移除账号统计和原始样本。
